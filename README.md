# てしごと堂 内職管理システム

小さな内職・在宅ワーク運営向けの業務アプリです。案件の受注から、内職者への出荷・入荷検品、顧客への納品、請求書、内職者支払、月報までを一つの画面の流れで扱います。

Google スプレッドシートは任意です。設定しなくても、見本データで一通り操作できます。

## ローカルで動かす

```bash
npm install
npm run dev
```

ブラウザで http://localhost:43123 を開きます。

本番相当の確認:

```bash
npm run build
npm start
```

業務ルールの検証:

```bash
npm run verify
```

データベースのアドレス（`DATABASE_URL` または `POSTGRES_URL`）が無いときは、データは `data/db.json` に保存されます（Git には含めません）。アドレスがあるときは Postgres に保存されます。店舗情報の「見本データに戻す」で業務データだけ初期状態に戻せます。変更した管理者パスワードと、内職者マイページのパスワードは残ります。

ログイン画面には、IDもパスワードも出ません。自分で入力します。ボタン一発で入る機能はありません。

管理者ログイン後、サイドバー左下の「文字の大きさ」で表示を大きくできます。内職者ポータルはスマホ幅でも使える想定です。

## 知っている人だけが見られるようにする

ログイン画面のアドレスを、教えた人だけが開けるようにできます。管理者用と内職者用は別です。内職者さんにはマイページ用だけを伝えてください。

環境変数が無いときは、今までどおり誰でもログイン画面を開けます。本番（Vercel や `npm start`）では、ログインした管理者の画面に「秘密のアドレスがまだ設定されていません」と出ます。入れなくなることはありません。自分のパソコンの `npm run dev` では、この注意は出ません。

設定したあとは、次のアドレスだけが入り口です。

- 管理者: `https://あなたのサイト/admin/login?key=管理者の鍵`
- 内職者マイページ: `https://あなたのサイト/portal/login?key=内職者の鍵`

正しい鍵で開くと、180日残るクッキーが付いて、鍵の無い普通のアドレスに移ります。ブックマークはそのあとのアドレスで大丈夫です。鍵が違う、またはクッキーが無いときは、ログイン画面ではなく「ページが見つかりません」と出ます。

### Vercel で設定する

1. 長いランダムな文字列を2つ作ります。例: ターミナルで `openssl rand -hex 24` を2回実行する
2. [Vercel のダッシュボード](https://vercel.com/dashboard) でプロジェクト **naisyoku-system** を開く
3. **Settings** → **Environment Variables** を開く
4. **Key** に `ADMIN_ACCESS_KEY`、**Value** に1つ目の文字列、環境は **Production** にチェックして保存する
5. 同じ場所で `PORTAL_ACCESS_KEY` に、別の文字列を保存する
6. **Deployments** から本番を **Redeploy** する。環境変数は、入れただけでは動いているサーバーに届きません
7. 管理者でログインし、左のメニューの **パスワード変更** を開く。そこに2つのアドレスと **コピー** ボタンが出ます
8. 管理者用は自分たちだけ、マイページ用は内職者さんに渡します

アドレスが他の人に漏れたときは、その環境変数を新しい文字列に変えて、もう一度 **Redeploy** します。古いアドレスと、すでに開いていた人のクッキーは使えなくなります。新しいアドレスを、渡してよい人だけに伝え直してください。

### 手元で開発するときの初期値

画面には出ません。このパソコンで、まだ一度もパスワードを変えていないときだけ使います。本番では環境変数 `ADMIN_ID` と `ADMIN_PASSWORD` を設定し、内職者のパスワードは内職者管理で設定してください。

| 画面 | ID | パスワード |
| --- | --- | --- |
| 管理者 | `tesigotodo` | `teshigoto@2026` |
| 内職者ポータル | `sato001` | `pass1234` |
| 内職者ポータル | `tanaka002` | `pass5678` |
| 内職者ポータル | `neko003` | `pass9012` |

## 管理者パスワードを変える

1. 管理者でログインする
2. 左のメニュー（スマホでは左上の ☰）の **パスワード変更** を開く
3. **現在のパスワード**、**新しいパスワード**、**新しいパスワード（確認）** を入れる
4. **パスワードを変更する** を押す
5. 「パスワードを変更しました」と出れば完了です。ログインし直さなくても、いまの画面のまま使えます

ルール:

- 新しいパスワードは 8 文字以上
- 確認用の入力と一致していること
- 今のパスワードと同じものは使えません
- ログイン ID は変わりません（環境変数 `ADMIN_ID`。未設定なら、上のローカル開発用の初期ID）

保存のしかた:

- パスワードそのものは保存しません。Node.js の scrypt でハッシュ化した値だけを保存します
- データベースに繋がっているときは、そのハッシュは業務データとは別の行（`adminAuth`）に入ります。繋がっていないときは、同じ `data/db.json` の `adminAuth` に入ります
- 変更したあとは、保存したハッシュと一致するパスワードだけが使えます。環境変数のパスワードでは入れません
- まだ一度も変更していないとき、または保存したハッシュが消えたときは、環境変数 `ADMIN_ID` / `ADMIN_PASSWORD` でログインします。未設定なら、上のローカル開発用の初期値です。入れなくなることはありません
- 「見本データに戻す」をしても、変更したパスワードは残ります
- パスワードを忘れたとき（ファイル保存）: `data/db.json` から `adminAuth` だけを削除すると、環境変数（未設定ならローカル開発用の初期値）のパスワードに戻ります。顧客や案件などのデータは消えません
- パスワードを忘れたとき（データベース）: Neon の SQL エディタで次だけを実行します。`db` の行は消さないでください

```sql
DELETE FROM app_store WHERE key = 'adminAuth';
```

## データをずっと残す（Vercel と Neon）

このアプリは、次の順で保存先を決めます。

1. 環境変数 `DATABASE_URL` があれば、それを使う
2. 無ければ `POSTGRES_URL` を使う
3. どちらも無ければファイルに書く。自分のパソコンでは `data/db.json`。Vercel 上では `/tmp` なので、サーバーが入れ替わると消える

データベースに繋がると、表 `app_store` を自動で作ります。中身は次の行です。

| key | 中身 |
| --- | --- |
| `db` | 顧客・案件・納品・請求などの業務データ |
| `adminAuth` | 管理者パスワードのハッシュ（平文は入れません） |
| `portalAuth` | 内職者ごとのマイページ用パスワードのハッシュ（平文は入れません） |

表が空のときだけ、見本データを入れます。すでに行があるときは上書きしません。保存は1行ずつ置き換えるので、同時に書き込んでも行が壊れません。業務データの保存はパスワードの行を消しません。`portalAuth` がまだ無いときだけ、見本の内職者3人分のパスワードをハッシュにして入れます。一度保存したあとは、空にして消した人のパスワードを見本に戻しません。平文のパスワードは入れません。

管理画面の上に、いまの保存先が出ます。

- **データベースに保存中** … Neon などに繋がっている
- **この公開先では…消えることがあります** … Vercel で、まだデータベースが無い
- **このパソコンのファイルに保存中** … 自分のパソコンで、データベースのアドレスが無い

データベースを繋いだあとの最初の起動は、見本データから始まります。Vercel の一時ファイルに入っていた内容は移しません。

### Neon を Vercel のプロジェクトに繋ぐ

有料のサービスは不要です。Neon の無料プランを、Vercel の Marketplace から繋ぎます。ボタン名は画面の更新で少し変わることがあります。確かめた流れは次のとおりです。

1. [Vercel のダッシュボード](https://vercel.com/dashboard) を開き、プロジェクト **naisyoku-system** を開く
2. プロジェクトの **Storage** を開く（データベースの置き場です）
3. Marketplace から **Neon** を選ぶ。一覧に無いときは [Neon の Marketplace ページ](https://vercel.com/marketplace/neon) を開き、**Add Integration**（または Install）を押す
4. プランは **Free**（無料）を選ぶ
5. 接続先のプロジェクトに **naisyoku-system** を選び、環境は **Production** にチェックを入れる（試し用の Preview も残してよい）
6. インストールを終える。Vercel が `DATABASE_URL` と `POSTGRES_URL` などを、そのプロジェクトの環境変数へ入れる
7. **Deployments** を開き、本番の最新デプロイで **Redeploy** を実行する。環境変数は、入れただけでは動いているサーバーに届きません。再デプロイが必要です
8. 管理画面を再読み込みし、上に「データベースに保存中」と出ていれば完了です

コマンドで入れる場合は、ログインした状態で `vercel integration add neon` を実行し、同じプロジェクトを選びます。終わったら、同じように再デプロイします。

### 管理者IDとパスワードの環境変数

本番の管理者IDとパスワードを変えるとき:

1. プロジェクト **naisyoku-system** の **Settings** → **Environment Variables** を開く
2. **Key** に `ADMIN_ID`、**Value** に使いたいIDを入れ、**Production** にチェックして保存する
3. 同じ場所で `ADMIN_PASSWORD` も追加する（8文字以上が安全です）
4. **Deployments** から本番を **Redeploy** する

画面の「パスワード変更」で変えたパスワードは、データベースにハッシュとして残ります。そのあとは環境変数のパスワードでは入れません。環境変数は、まだ一度も変えていないときと、上の SQL でハッシュを消したあとに使われます。

## 日常の流れ

1. **発注元（顧客）** を登録する  
2. **案件** で受注数量・顧客単価・内職単価を登録する  
3. **出荷登録** で内職者に数量を割り当てる（受注数を超える出荷はできません）  
4. 戻ってきたら **入荷検品**（出荷数を超える入荷はできません）  
5. **納品管理** で顧客へ渡した数量を記録する（受注数を超える納品はできません）  
6. **請求・支払** で顧客×月の未請求分から請求書を発行する  
7. 同じ画面の支払一覧／明細書で、入荷完了分だけを内職者へ支払う  
8. **月報** で売上と報酬を確認する  

ダッシュボードに「次に進める作業」が出ます。行き詰まったらそこから進めてください。

## Google スプレッドシート（任意）

本番でシート連携する場合は [docs/GOOGLE_SHEETS_SETUP.md](docs/GOOGLE_SHEETS_SETUP.md) を参照してください。秘密鍵やサービスアカウント JSON はリポジトリに置かないでください。`.env.local` のみで管理します。

## 注意

- 見本の顧客・内職者は架空です。実在の個人情報は入れないでください。
- 本番では環境変数 `ADMIN_ID` / `ADMIN_PASSWORD` を設定してください。画面から変えたパスワードは、データベースに繋がっていれば残ります。繋がっていない Vercel では消えることがあり、そのときは環境変数（未設定ならローカル開発用の初期値）で入れます。残し方は上記「データをずっと残す」を見てください。ログイン画面にはパスワードを出しません。
- 内職者マイページのパスワードは、事務所が内職者ごとに設定します。ログイン画面には出しません。

## 内職者マイページのパスワード

事務所が設定します。内職者さん自身でも、あとから変えられます。パスワードそのものは保存せず、scrypt のハッシュだけを `portalAuth` に入れます。画面や `/api/db` には出しません。

### 事務所が設定する

1. 管理者でログインする
2. 左のメニューの **内職者管理** を開く
3. **新規内職者登録** または一覧の **編集** で、**マイページ用ログインID** と **マイページ用パスワード** を入れる。編集のとき、パスワードを空欄のまま保存すると、今のパスワードのままです
4. 一覧の **パスワード設定** からも、その人だけのパスワードを変えられます。ログインIDもここで直せます
5. 一覧の「マイページ」列に、ログインIDと **設定済み** または **未設定** が出ます。パスワードの中身は出ません

パスワードが未設定の人は、マイページに入れません。ログイン画面に「事務所に連絡して、マイページ用パスワードを設定してもらってください」と出ます。

### 内職者さんが自分で変える

1. マイページにログインする（`/portal/login`）
2. 上の **パスワード変更**、または個人情報の **パスワード変更** を開く（`/portal/password`）
3. **現在のパスワード**、**新しいパスワード**、**新しいパスワード（確認）** を入れる
4. **パスワードを変更する** を押す

ルールは管理者のパスワード変更と同じです。8文字以上、確認用と一致、今のパスワードとは別のもの。変えたあともログアウトせずにマイページを使えます。古いパスワードでは入れなくなります。

「見本データに戻す」をしても、設定したマイページ用パスワードは残ります。忘れたときは、内職者管理の **パスワード設定** で新しいものを入れてください。
