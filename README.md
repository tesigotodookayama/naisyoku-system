# てしごと堂 内職管理システム

小さな内職・在宅ワーク運営向けの業務アプリです。案件の受注から、内職者への出荷・入荷検品、顧客への納品、請求書、内職者支払、月報までを一つの画面の流れで扱います。

Google スプレッドシートは任意です。設定しなくても、見本データで一通り操作できます。

## ローカルで動かす

```bash
npm install
npm run dev
```

ブラウザで http://localhost:43123 を開きます。

本番相当の確認:

```bash
npm run build
npm start
```

業務ルールの検証:

```bash
npm run verify
```

データは `data/db.json` に保存されます（Git には含めません）。店舗情報の「見本データに戻す」で初期状態に戻せます。

## 見本ログイン

| 画面 | ID | パスワード |
| --- | --- | --- |
| 管理者 | `tesigotodo` | `teshigoto@2026` |
| 内職者ポータル | `sato001` | `pass1234` |
| 内職者ポータル | `tanaka002` | `pass5678` |
| 内職者ポータル | `neko003` | `pass9012` |

ログイン画面の「見本アカウントで入る」（内職者は各行の「入る」）を押すと、上の見本アカウントで入れます。手入力でも同じです。管理者パスワードを変更したあとは、見本のパスワードと「見本アカウントで入る」は使えなくなります。

管理者ログイン後、サイドバー左下の「文字の大きさ」で表示を大きくできます。内職者ポータルはスマホ幅でも使える想定です。

## 管理者パスワードを変える

1. 管理者でログインする
2. 左のメニュー（スマホでは左上の ☰）の **パスワード変更** を開く
3. **現在のパスワード**、**新しいパスワード**、**新しいパスワード（確認）** を入れる
4. **パスワードを変更する** を押す
5. 「パスワードを変更しました」と出れば完了です。ログインし直さなくても、いまの画面のまま使えます

ルール:

- 新しいパスワードは 8 文字以上
- 確認用の入力と一致していること
- 今のパスワードと同じものは使えません
- ログイン ID は変わりません（環境変数 `ADMIN_ID`。未設定なら `tesigotodo`）

保存のしかた:

- パスワードそのものは保存しません。Node.js の scrypt でハッシュ化した値だけを、業務データと同じ `data/db.json` の `adminAuth` に保存します
- 変更したあとは、そのハッシュと一致するパスワードだけが使えます。見本パスワードや `ADMIN_PASSWORD` では入れません
- まだ一度も変更していないとき、または保存が消えたときは、環境変数 `ADMIN_ID` / `ADMIN_PASSWORD`（未設定なら見本の `tesigotodo` / `teshigoto@2026`）でログインします。入れなくなることはありません
- 「見本データに戻す」をしても、変更したパスワードは残ります
- パスワードを忘れたとき: `data/db.json` から `adminAuth` だけを削除すると、環境変数（未設定なら見本）のパスワードに戻ります。顧客や案件などのデータは消えません

### Vercel で公開している場合

本番（例: naisyoku-system.vercel.app）では、データを `/tmp` に書きます。`/tmp` はサーバーが入れ替わったり再デプロイしたりすると消えます。`data/db.json` への書き込みは、Vercel 上では残らないことがあります（顧客データも同じです）。

そのため、画面で変えたパスワードも消えることがあります。消えたあとは、環境変数 `ADMIN_PASSWORD`（未設定なら見本のパスワード）で再びログインできます。変更したパスワードが残っているサーバーに当たったときだけ、新しいパスワードが必要です。

パスワードをずっと残すには、ファイルではなくデータベースに保存する必要があります。このリポジトリには有料の外部サービスは追加していません。残す場合は、Vercel Marketplace の Postgres（Neon など）または KV（Upstash など）に `adminAuth` を保存してください。画面の「パスワード変更」でも、Vercel 上では同じ注意が出ます。

## 日常の流れ

1. **発注元（顧客）** を登録する  
2. **案件** で受注数量・顧客単価・内職単価を登録する  
3. **出荷登録** で内職者に数量を割り当てる（受注数を超える出荷はできません）  
4. 戻ってきたら **入荷検品**（出荷数を超える入荷はできません）  
5. **納品管理** で顧客へ渡した数量を記録する（受注数を超える納品はできません）  
6. **請求・支払** で顧客×月の未請求分から請求書を発行する  
7. 同じ画面の支払一覧／明細書で、入荷完了分だけを内職者へ支払う  
8. **月報** で売上と報酬を確認する  

ダッシュボードに「次に進める作業」が出ます。行き詰まったらそこから進めてください。

## Google スプレッドシート（任意）

本番でシート連携する場合は [docs/GOOGLE_SHEETS_SETUP.md](docs/GOOGLE_SHEETS_SETUP.md) を参照してください。秘密鍵やサービスアカウント JSON はリポジトリに置かないでください。`.env.local` のみで管理します。

## 注意

- 見本の顧客・内職者は架空です。実在の個人情報は入れないでください。
- 管理者の見本パスワードはデモ用です。本番では環境変数 `ADMIN_ID` / `ADMIN_PASSWORD` を設定してください。画面からの変更は、ローカルでは `data/db.json` に残ります。Vercel では消えることがあるので、消えても見本または環境変数のパスワードで入れます。長く使うにはデータベースへ保存してください（上記「Vercel で公開している場合」）。
- 内職者ポータルのパスワードは見本用の固定値です。管理画面からの変更には対応していません。
